# MC02 / M3508 单电机前馈与速度 PI 台架

2026-10-19。状态：独立软件实现；编译 / 主机 / 数值验证见末节；**未烧录、未接电机、未实测停机或跟踪性能**。
分支 `bench/m3508-control`，独立工作树 `COD_RoboCore_m3508`；不合并 main，原目录用户修改不参与本构建。
用户授权此独立固件；英雄、底盘和 DM4340 手拖应用各自保留。

## 配置、接线与构建

- 对象：一台 M3508 P19 + C620，原装减速箱、空载固定台架。不可把别的电机或带轮 / 机构的负载当成这台裸电机模型。
- MC02 **CAN1 / FDCAN1 经典 CAN 1 Mbit/s** 接 C620，ID 1。电机组只发 `0x200` 第一槽，其他槽为零；反馈 `0x201`。
  以实物丝印核对接线、终端和 ID。CAN3 在当前工程是 FD+BRS，不沿用 DM4340 的接法。
- DR16 接 MC02 的 DBUS / UART5；USB 接 MC02 本身，电脑下发本次参数并记录，不触发轨迹。启动不创建底盘、电容、IMU 或加热任务。
- 参数唯一位置：`01_applic/config/motor_bench_robot.h`；输出轴 rad/s、N·m，设备层按同一名义 Kt 换成 C620 电流。
  模型及三档 PI 候选来自系统辨识仓库 `docs/cn/results/m3508_control_candidate.md` / #72，全部为等效单位。
- 模型源数据仅覆盖 26–27 °C。启动 / 过热保护与模型适用温度分别处理：
  采用用户 2026-10-19 确认的启动上限 / 运行停机温度，不代表模型已验证到这些温度；A/B 必须记录并控制温度漂移。
  这些边界是试验约束，不是验证过的硬件能力。控制超期 / 执行时间保护仍是待台架审核的试验设置。

WSL 在本工作树根目录运行：

```bash
cmake --preset h723-m3508
cmake --build --preset h723-m3508
```

产物 `build/Linux/h723-m3508/COD_RoboCore.elf`。Ozone 必须显式选择此 ELF；不要沿用底盘或手拖工程的旧 ELF 路径。
Keil 目标仍为原底盘，本台架只提供专用 CMake 预设。CubeMX 生成代码未修改。
烧录和任何上板 / 接电机操作由用户确认并完成。

## 默认只记录，怎样准备一次试验

每次上电 `motor_bench.settings.allow_motion=false`。在辨识平台“车上辨识”中选择“MC02 M3508 + C620 单电机”，
打开“本次试验设置”。先选“只记录”；现场验证完成后才选“准备单次 PI / 前馈试验并记录”。
启动记录时下发配置，MCU 控制任务应用后返回实际值；拒绝、超时或回读不一致均报失败。
只有 DR16 下档、遥控和电机反馈在线且轴速不超过配置的静止线时允许整组修改；运行中拒绝，失败不部分应用。
参数只存 RAM；复位恢复默认并撤销运动准备。电脑不代替拨杆启动，也不写 Flash。

| 设置 | 固件允许范围 / 含义 |
|---|---|
| 总出力 | 正值且不超过配置上限；PI + 前馈共用，积分自身也受该界限限制；界面 A 按名义 Kt 换为 N·m |
| 运动速度窗口 | 配置默认窗口的子区间，下界必须小于上界 |
| 加速度 | 正值且不大于配置默认值 |
| 超速线 | 大于本次速度上界，且不大于配置默认超速线；降低阈值表示更早撤流 |
| 启动温度上限 / 运行停机温度 | 均不大于配置对应默认值，前者小于后者；启动严格 > 拒绝，运行 ≥ 撤流 |
| 方向 / PI 档 / 前馈 | 正反分别运行；档号对应 `tc_s[]`；PI 与同档 PI + 前馈对照 |
| 周期 / 反馈年龄 / 丢数 | 仅电脑分析，不改变固件保护；默认仍标为草案 |
| A/B 收益 / 漂移 | 预登记并随日志保存，当前窗口不自动比较三个运行 |

边界和默认值唯一代码来源：`01_applic/config/motor_bench_robot.h`（用户 2026-10-19 确认的试验包络）。
当前固件不接受超过该包络的页面设置；未采用此前建议的更高电流 / 温度值。
正常结束、停止和可处理异常均请求撤销运动准备并核对回执；USB 不通时只报告未确认，不能据此判断电机已停。

DR16 使用 `sw[1]`，先在 Ozone 核对它对应哪个实体拨杆：

1. 下档：每拍明确请求零力矩，清积分；轴静止且输入健康时登记重新准备。
2. 下→中：进入 READY，仍为零力矩。直接上电中 / 上档不会运行。
3. 中→上：冻结选择，触发一次定长轨迹。
4. 上→中或下：撤请求、清积分；需重新下→中才可再运行。
5. 完成或任何故障后保持撤请求；恢复反馈或遥控不会自行重启。

故障包括遥控 / 电机失联、驱动错码、超速、温度越界、控制超期、上一拍 CAN 提交失败、运动阶段跟踪或速度范围不满足。
故障与模式枚举见 `motor_bench.h`，在 Ozone 看 `motor_bench`。默认无运动授权时仅记录设备状态，不触发运动状态机。
本应用持续发送零电流作为停止动作；C620 停发 / 断总线后的物理行为尚未实测，通信完全中断时固件不能保证撤流。
必须有现场可立即切断的电机电源；先测停止 / 失联，再跑完整轨迹。电脑拔 USB、Ctrl+C 或关记录器不是急停。

## 轨迹与前馈范围

轨迹速度与加速度取本次已确认参数，时长取固件配置；本节展示其结构：

| `bench.phase` | 参考 | 前馈 |
|---:|---|---|
| 0 | 从静止斜坡到低速 | PI 起步，不补静摩擦、不起步助推 |
| 1 | 低速稳定 | PI |
| 2–5 | 低→高、保持、高→低、保持 | 根据选择启用摩擦 + 规划加速度前馈 |
| 6 | 低速斜坡到零 | PI 停止 |
| 7 / DONE | 试验结束 | 请求零电流并清积分 |

起步 / 停止不属于已验证运动摩擦模型。稳定期后未达到配置的运动范围或跟踪条件就锁定，不自动增大电流。
进入 / 离开前馈区间时，将低速恒速摩擦份额在积分和前馈之间转移；规划加速度项仍作用于加减速。
积分状态直接用 N·m 保存，每拍用真实 dt 积分，只在不继续加深 **PI + 前馈总饱和** 时接受累加。
此逻辑属于独立模块，通用 `03_algorithm/control/pid.c` 未修改。

## 记录、对齐与验收

在 System_Identification 仓库，用已有记录器；端口换成 MC02 实际端口：

```bash
python tools/sysid_log/sysid_log.py --port COM5 --out data/m3508_mc02/runs --label pi_check --subject "MC02 M3508 C620 speed bench" --seconds 30 --vbus 24 --firmware-repo ../../COD_RoboCore_m3508
```

上述 CLI 仅被动记录，不准备运动；页面会额外传 `--bench-settings` / `--bench-criteria` JSON，格式见辨识仓库 `docs/cn/firmware_module.md`。
不要加 `--axis`。固件 sysid 轴表为空，电脑不能激励。协议是本队 MIT 快照，来源 / 原文 SHA-256 在
`01_applic/modules/motor_bench/telemetry/README.md`。导出 CSV 用现有 `decode_sysid_stream.py`。

36 个标量、目标 1 kHz，按 sysid 帧公式为 182 kB/s；这只是计算，不是 USB 吞吐实测值。
通信任务发送；控制任务仅生产记录，USB 忙时不会等待。检查记录头 `dropped`、序号及真实采样间隔；
一旦丢数或抖动使目标频段不可分析，该运行不用于延迟 / PID 验证，先处理采集。

- `motor.w/q/tau/temperature/current`：反馈；力矩 / 电流为名义尺度，不是额外力矩传感器。
- `control.reference/acceleration/pi/integral/requested/command`、`ff.*`：控制各项、总限幅前后出力。
- `can.raw_current`：最终编码的 C620 第一槽整数；`can.tx_accepted` 仅代表进硬件队列，不证明总线发送或电机执行。
- `motor.fb_stamp`、`can.tx_stamp`：同一 1 MHz 时钟的低 32 位，需要按记录时间解回回绕；前者是接收中断时间，后者是提交前时间。
  `motor.fb_sequence`、`motor.fb_age` 区分本拍复用的旧反馈和新样本。
- 记录主时间是本拍读完输入的时刻；`control.period` 是两次控制开始间隔，`bench.elapsed` 是本拍参考时间。
  `control.exec` 是本拍记录入队前的耗时；超期检查用上一拍包含记录入队的完整耗时。
- `bench.mode/phase/fault/gain/direction/motion_allowed`、`rc.*`、`can.tx_dropped`、`motor.error_code`：解释运行条件和中止原因。

最小台架顺序（用户操作）：先无运动授权记录零电流 / 拨杆映射 → 核对供电、夹具、温度、方向与本次限流 →
仅 PI 短启动，刚起转就下档并测撤流 / 停转 → 分别测遥控丢失、反馈断开、停发及重连不重启 → 通过后再跑完整定长轨迹。
起步失败、中止、限幅或过热都保留日志，不靠手推 / 突然增流让正式试验继续。

固定增益、方向、负载及温度，依次 PI → 同一 PI+前馈 → PI；每次更改设置前回下档、停轴。
正反分别采样。预先封存新 holdout；运动段与起步 / 停止段分开评分，同时报告整段是否完成及所有中止。
指标至少含跟踪 RMS / 最大误差、超调、稳定时间、出力 RMS / 峰值、饱和时间和真实停止行为。
只有实测对照通过预定指标，才可接受某组参数；当前离线数值不能承诺实机提升比例。
