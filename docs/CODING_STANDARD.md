# COD RoboCore 编码规范

版本：草案 v0.4（2026-09-28：并入原《架构设计》“C 编码规范要点”表中本规范没有的 5 条；v0.3 按“只写必要的安全代码”精简，见 ADR 0026）

本规范是架构规范《架构设计》（`docs/ARCHITECTURE.md`）中“编码规范”一节的细则。**本规范写得更细的地方，以本规范为准；两者冲突时，先提出来，统一修改，不要各按各的写。**

v0.2 融合了队内原有的《嵌入式代码规范》：它提出的 8 条目标，放在第 1.1 节，并逐条对应到本规范的具体规则。

## 0. 适用范围与用词

**适用于**本仓库中手写的 C 代码：`05_platform/`、`04_core/`、`03_algorithm/`、`02_devices/`、`01_applic/`、`tests/`。

**不适用于**以下代码，并且**不要修改它们**：
- CubeMX 生成的代码：只在 `USER CODE BEGIN … END` 区域里写，区域里的代码遵守本规范；
- 第三方代码：HAL、CMSIS、FreeRTOS、SEGGER RTT、Unity 等。

规则的强度分三级：

| 用词 | 含义 |
| --- | --- |
| **必须** | 违反即视为缺陷，代码审查不通过 |
| **应该** | 默认这样做；不这样做时，在代码注释或提交说明里写明理由 |
| **可以** | 允许，由作者判断 |

## 1. 目标与取舍顺序

### 1.1 目标

写代码时追求以下 8 条（来自队内《嵌入式代码规范》）。右列是本规范里落实它的规则；目标是方向，具体做法以右列的规则为准。

| 目标 | 在本规范中怎么落实 |
| --- | --- |
| (1) 代码简洁精炼、美观，可持续维护 | 统一用 `.clang-format` 格式化（第 5 节）；函数只做一件事（9.2）；注释解释原因（第 6 节） |
| (2) 高效率 | 满足实时预算即可，**先测量再优化**（1.2）；热路径不做重复检查（第 2 节）；只用 `float`（第 7 节） |
| (3) 高复用，可移植性好 | 芯片相关代码只在 `05_platform/`、`06_boards/`（第 12 节）；这台车的差异只在 `robot_config.h`（第 10 节）；通用计算放在 `03_algorithm/` 里复用（7、10 节） |
| (4) 高内聚，低耦合 | 一个模块 = 一个结构体 + 一组函数（9.2）；全局变量加 `static`（第 8 节）；子系统之间只通过话题交换数据（第 11 节） |
| (5) 没有冗余 | 同一个条件只在边界检查一次（第 2 节）；不用 `#if 0` 保留废弃代码（第 10 节）；重复的计算抽到 `03_algorithm/`，而不是复制粘贴 |
| (6) 规范性，有规可循 | 本规范的“必须 / 应该 / 可以”分级（第 0 节）；代码审查清单（第 18 节） |
| (7) 特殊排版、特殊语法、特殊指令必须特别说明 | 第 6.1 节：`clang-format off`、编译器属性、`#pragma`、内联汇编、内存屏障、位运算技巧等必须写注释 |
| (8) 上手简单、易于移植、复用性高、层级分明、结构清晰 | 分层依赖规则（第 12 节及《架构设计》）；模块文档（第 16 节）；取舍顺序把“可读与架构清晰”放在性能之前（1.2） |

### 1.1a 一处定义（用户 2026-10-01 定，ADR 0050）

- **必须**：**一个参数，一个定义位置。** 同一个数（常数、换算系数、ID、总线号、阈值）只在一个地方写，别处引用它；
  注释里也不要再抄一遍具体数值（会和代码不一致），写“见某文件”。各参数的位置见 `01_applic/README.md`“参数在哪里”。
- **必须**：**一个状态，一个权威来源。** 一个状态只有一个对象持有、一个任务负责写；读的一方直接读它（或通过它的读函数），
  不另存一份副本再同步。例：模式只在 `safety_gate`，电池状态只在 indicator_task。
- **必须**：**一项职责，一个负责模块。** 一项工作从初始化、启动到周期处理都在同一个模块里，不分散到几个文件。
  例：状态灯、蜂鸣器只有 indicator_task 操作，CAN 接收和 bus-off 恢复都在 comm_rx_task。
- **必须**：**同种工作不散乱。** 通用的代码只写一份（放 `01_applic/system/` 或对应机构目录），`01_applic/robot/` 只放这台车不同的东西。

### 1.2 取舍顺序

目标之间可能冲突。例如为了“高效率”省掉一次检查，可能影响“正确”；为了“没有冗余”合并两段代码，可能影响可读性。规则之间冲突、或者拿不准时，按以下顺序取舍：

> **正确 > 可读与架构清晰 > 性能 > 额外的防御性检查**

- **正确**：功能符合需求，也符合接口约定。**项目要求的安全机制属于“正确”，不属于“额外的防御性检查”**，不能以性能或简洁为理由省略。这些机制包括：全车停（急停、遥控丢失）及其统一出口、机构停（本机构设备离线）、执行器安全动作、硬件看门狗、上电不自动使能。
- **只写必要的安全机制**：每个安全机制都要能说出它防的是哪个具体故障；同一故障已有一处处理的，不加第二道；“以防万一”的检查、统计和报警不加。
- **可读与架构清晰**：新队员能顺着目录和注释读懂；依赖方向符合分层规则。
- **性能**：满足实时预算即可，不为了省几个时钟周期牺牲可读性。需要优化时，先测量，再优化。
- **额外的防御性检查**：为理论上可能、按接口约定不应发生的情况所加的检查。优先级最低，见第 2 节。

## 2. 检查只做一次：边界检查，内部按约定

**必须**在**边界**检查输入，并且只在那里检查一次：

| 边界 | 检查什么 |
| --- | --- |
| 外部数据进入系统的地方：串口帧、CAN 帧、遥控、上位机、裁判系统、Flash 参数 | 帧长度、CRC、字段取值范围、NaN |
| 初始化和配置 | 配置能否支持（例如电机型号是否支持力矩指令）、资源是否冲突（CAN ID、滤波器数量） |

边界之内：

- **必须**把前提条件写进接口注释的 `@pre`，调用方负责满足。
- **不要**在调用链的每一层重复检查同一个条件。例如，电机型号是否支持力矩指令，在 `xxx_init()` 里检查一次；运行时每个周期不再重复检查。
- **不要**在 1 kHz 的热路径上检查实例指针是否为 `NULL`：指针在初始化时就确定了，出错会在上电测试中暴露。
- `RM_ASSERT` 用于捕获**编程错误**，适合放在初始化和公开接口的入口，不要撒在热路径的每个函数里。

```c
/* ✅ 在边界检查一次：设备层解析 CAN 帧时校验，之后的层直接使用 */
static void dji_motor_on_frame(DjiMotor *self, const CanFrame *frame)
{
    if (frame->len != 8)
    {
        self->bad_frame_count++;
        return;                     /* 不合法的帧：丢弃，不喂狗 */
    }
    /* 解析、换算成 SI 单位、写入反馈快照 */
}

/* ❌ 同一个条件层层重复检查：子系统、电机组、驱动都再判断一次 */
void gimbal_step(Gimbal *self, ...)
{
    if (self == NULL || self->yaw_motor == NULL) { return; }
    if (!motor_supports_torque(self->yaw_motor)) { return; }   /* init 时已经检查过 */
    ...
}
```

**安全机制不受本节“少检查”的影响。** 例如：
- 在线判断每个周期都要按时间戳计算；
- 全车停的统一出口每个周期都要执行；
- 遥控丢失、急停每个周期都要读取。

这些是项目要求的功能，不是重复的防御性检查。

## 3. 文件与编码

- **必须**：UTF-8（无 BOM）、LF 换行、文件以换行结尾。由 `.gitattributes` 和 `.editorconfig` 保证；从旧工程迁移的 GBK 文件，要先转码再提交。
- **必须**：头文件使用 `#pragma once`，并且能**单独编译**，即自己 include 所需的全部头文件。
- **必须**：头文件带 `extern "C"` 保护，方便可选的 C++ 模块调用。
- **应该**：一个模块对应一对 `xxx.c` / `xxx.h`，文件名与模块名一致，全部小写加下划线。
- **必须**：任务文件都放在 `01_applic/tasks/`（ADR 0057）。
  任务只写“什么时候跑、按什么顺序调用谁”，计算放进 `modules/` 等其他文件。
- **必须**：任务的文件、入口函数、任务名都以 `_task` 结尾：`detect_task.c`、`detect_task_entry`、任务名 `"detect_task"`；
  不是任务的文件不要以 `_task` 结尾（例：接收的公共函数叫 `comm_rx_common.c`，任务本身是 `comm_rx_task.c`）。
- **应该**按以下顺序 include，组与组之间空一行：
  1. 本模块自己的头文件；
  2. C 标准库；
  3. 本项目其他层的头文件；
  4. 第三方库。
- **必须**：本项目其他层的头文件从仓库根目录写起，**带层的编号**，如 `#include "05_platform/can/can.h"`、`#include "01_applic/modules/chassis/chassis.h"`（ADR 0046）；
  本模块自己的头文件和同目录的头文件只写文件名（如 `#include "chassis.h"`、`#include "robot.h"`）。
- **必须**：芯片厂商的头文件（CubeMX 生成的 `adc.h`、`spi.h`、`fdcan.h`，HAL、CMSIS）用尖括号 `#include <adc.h>`。
  `05_platform/<外设>/` 里有本模块自己的同名接口头文件，引号会先在当前目录找到它。
- **应该**：文件开头写 Doxygen 文件头：

```c
/**
 * @file    dji_motor.c
 * @brief   DJI 电机（M3508 / M2006 / GM6020）的协议解析与指令打包
 * @note    协议依据：《架构设计》附录 A.2
 */
```

## 4. 命名

标识符一律用英文。**不用拼音，也不用拼音首字母。**

| 对象 | 规则 | 例子 |
| --- | --- | --- |
| 类型（结构体、枚举、typedef） | **必须** `PascalCase` | `Motor`、`RobotCmd`、`SafeAction` |
| 函数 | **必须** `模块_动作`，全小写加下划线 | `motor_set_torque()`、`robot_cmd_read()` |
| 变量、结构体成员、参数 | **必须** `snake_case` | `yaw_err_rad`、`feedback` |
| 宏、枚举常量 | **必须**全大写，并带模块前缀 | `SAFE_ACTION_DAMP`、`ERR_CAN_BUS_OFF` |
| 文件内的私有函数和变量 | **必须**加 `static`；名字可以不带模块前缀 | `static void parse_frame(...)` |
| 布尔变量和返回 bool 的查询函数 | **应该**读起来是一句判断 | `is_online`、`has_error`、`motor_is_enabled()` |

- 从旧工程迁移的模块，第一版**可以**保留原函数名，第二步再改名（先搬代码、再改行为）。
- **应该**只用附录 A 里的缩写。其他单词写全称。

### 4.1 单位后缀

物理量的单位靠名字表达，编译器不检查，所以对**跨越模块边界**的量要求最严，对函数内部的临时量放宽。

| 位置 | 要求 |
| --- | --- |
| 公开接口：结构体成员、函数参数、返回值、消息和话题字段、`robot_config.h` 中的常量 | **必须**带单位后缀，或者在注释里写明单位 |
| 模块内部的状态（`.c` 文件中的结构体成员、静态变量） | **应该**带单位后缀 |
| 函数内几行就用完、单位一眼能看出来的临时变量 | **可以**不带 |
| 无量纲的量（比例、计数、索引、布尔值） | 不需要后缀；比例建议写成 `_ratio` |

后缀的含义见《架构设计》“单位后缀”表：`_rad`、`_rad_s`、`_m_s`、`_nm`、`_a`、`_v`、`_w`、`_ms`、`_us` 等。**对外接口一律用 SI 单位**；`_rpm`、`_deg`、`_raw` 只在设备层内部或配置输入中出现。

```c
/* ✅ 公开字段带单位；函数内部短暂使用的临时量可以不带 */
typedef struct
{
    float yaw_target_rad;   /**< 目标航向，W 系，逆时针为正 */
    float yaw_ff_rad_s;     /**< 航向角速度前馈 */
} GimbalCmd;

static float wrap_error(float target_rad, float measure_rad)
{
    float err = target_rad - measure_rad;   /* 局部临时量，单位与参数相同 */
    return angle_wrap_pi(err);
}

/* ❌ 公开字段没有单位，读者无法判断是度还是弧度、是转子还是输出轴 */
typedef struct
{
    float yaw;
    float speed;
} GimbalCmd;
```

## 5. 格式

- **必须**使用仓库根目录的 `.clang-format` 格式化。提交前运行一次，**不要手动对齐**去对抗它。
  - 花括号用 **Allman 风格**：`{` 单独占一行。
  - 缩进 4 个空格，每行不超过 100 列。
  - `if` / `else` / `for` / `while` 的语句体**必须**加花括号，只有一行也要加。
- 只有表格状的数据（如寄存器表、参数表）**可以**用 `// clang-format off` / `// clang-format on` 包起来保留手工排版，并且要写明原因（6.1）。

```c
/* ✅ */
if (!is_online)
{
    return false;
}

/* ❌ 没有花括号，后来的人再加一行时很容易写错 */
if (!is_online)
    return false;
```

## 6. 注释

- 注释**使用中文**，专业术语可以保留英文，如 CRC、DMA、Kp。
- **必须**给公开接口写 Doxygen 注释，写在**头文件的声明处**，`.c` 文件里的定义不再重复。按适用情况写清：
  - `@param` / `@return`：单位、坐标系、取值范围；
  - `@pre`：调用方必须满足的前提（见第 2 节）；
  - `@note`：调用上下文。能在任务里调用，还是能在中断里调用。
- **应该**让注释解释**为什么**，而不是复述代码做了什么。硬件限制、数据手册勘误、看起来不对但实际是对的写法、被否决的方案，都值得写。
- `TODO` 和 `FIXME` **必须**带姓名和日期：`/* TODO(xalve, 2026-09-25): ... */`。

```c
/**
 * @brief 设置电机输出轴力矩。
 * @param self       电机实例。
 * @param torque_nm  输出轴力矩，单位 N·m，正方向按 MotorConfig.direction 约定。
 * @pre   该电机在 motor_init() 时已确认支持力矩指令。
 * @note  只能在 control_task 中调用；本函数只写入电机组的槽位，不立即发送。
 */
void motor_set_torque(Motor *self, float torque_nm);
```

```c
/* ✅ 解释原因 */
/* 阻塞读取：17 字节约 18 µs，占 1 kHz 周期的 1.8%，改成 DMA 不值得（见 docs/budget.md） */

/* ❌ 复述代码 */
/* 调用 spi_transfer 读取数据 */
```

### 6.1 特殊写法必须说明

下列写法读者一眼看不出用意，改错了往往也不会报错。**必须**在旁边写注释，说明“为什么非这样写不可”：

| 写法 | 例子 |
| --- | --- |
| 关闭自动格式化 | `// clang-format off` |
| 编译器属性、段放置、对齐 | `__attribute__((section(".dma_buf"), aligned(32)))`、`packed`、`weak` |
| `#pragma` | `#pragma GCC diagnostic ignored ...` |
| 内联汇编、内存屏障、Cache 操作 | `__DSB()`、`__ISB()`、`SCB_InvalidateDCache_by_Addr()` |
| 直接操作寄存器（只允许在 `05_platform/`、`06_boards/` 中） | `FDCAN1->TXBAR = ...` |
| 位运算技巧、定点换算、非常规的整数与浮点转换 | `(x + 3) & ~3u`、协议里 12 位量的拼接 |
| 故意为之、看起来像 bug 的写法 | 故意不加锁、故意丢弃返回值、`switch` 的贯穿（fall-through） |

```c
/* ✅ */
/* H7 的 DMA1/DMA2 访问不到 DTCM，缓冲区必须放在 AXI SRAM；该段已由 MPU 设为不可缓存（ADR 0021） */
RM_DMA_BUF static uint8_t dr16_rx_buf[2][18];

/* ❌ 没有说明：以后有人“顺手”删掉这个宏，编译照样通过，运行时却什么都收不到 */
RM_DMA_BUF static uint8_t dr16_rx_buf[2][18];
```

## 7. 类型与数值

- **必须**用 `<stdint.h>` 的定宽整数类型（`uint8_t`、`int32_t` 等）表示协议字段和寄存器值；表示布尔值时用 `<stdbool.h>` 的 `bool`。
- **必须**只用 `float`，不用 `double`：
  - 浮点常数带 `f` 后缀；
  - 数学函数用 `f` 版本，如 `sinf`、`sqrtf`、`atan2f`；
  - 编译选项开启 `-Wdouble-promotion`。

  不带 `f` 的常数会让整个表达式变成 double，在 F407 上是软件模拟运算，在 1 kHz 控制环里代价很高。
- **必须**在边界上把原始整数换算成 SI 浮点（第 2 节）；把浮点换算回协议整数时，**必须**先限幅再转换，不允许溢出回绕。
- 角度回绕**应该**统一用 `03_algorithm/` 里的函数，不要每处各写一遍 `while (x > PI)`。
- **必须**：判定“是否正常”的阈值不能依赖采样数量。例如判断静止用**标准差**，不用峰峰值：峰峰值会随采样数增大，
  导致标定一直失败却没人发现（UniC 在陀螺零偏标定上实际遇到）。

```c
/* ✅ */
const float gear_ratio = 3591.0f / 187.0f;
float out = sinf(angle_rad) * 0.5f;

/* ❌ 3591.0 / 187 和 0.5 都是 double，sin() 也是 double 版本 */
float gear_ratio = 3591.0 / 187;
float out = sin(angle_rad) * 0.5;
```

## 8. 内存与存储期

- **必须**：不调用 `malloc` / `free` / `calloc` / `realloc`。所有对象静态分配，或由调用方提供存储。
- **必须**：全局变量一律加 `static`，其他文件通过函数访问；全局变量只写常量初值，硬件相关的初始化放在显式的 `xxx_init()` 里。
  **例外**（ADR 0044）：`01_applic/robot/` 的对象（话题、设备、子系统、安全门）定义在 `robot.c`、声明在同目录 `robot.h`，
  供 `01_applic/tasks/` 里的任务直接使用；其他层不得 include `robot.h`。
- **必须**：不写递归，不用变长数组（VLA）；较大的缓冲区（几百字节以上）不放在栈上。
- **必须**：DMA 缓冲区用 `RM_DMA_BUF` 声明，BDMA 缓冲区用 `RM_BDMA_BUF` 声明（ADR 0021）。
- **必须**：`volatile` 只用于硬件寄存器和中断里置位的简单标志，**不能**当作任务之间的同步手段。跨任务共享的数据走话题或临界区。
- **应该**：只在通信帧结构上用 `packed`，并且不对 packed 结构体的成员取地址。
- **应该**：配置（`const XxxConfig`）和运行状态（`Xxx`）分成两个结构体。

```c
/* ✅ 调用方提供存储，初始化时关联配置 */
static const MotorConfig yaw_config = { .type = MOTOR_GM6020, .can_bus = CAN_BUS_1, .id = 1 };
static Motor yaw_motor;

/* ❌ 运行时分配 */
Motor *yaw_motor = malloc(sizeof(Motor));
```

## 9. 函数与接口

### 9.1 返回值约定

按“失败是否可能发生、调用方能否处理”来选返回类型，**不要求**所有函数都返回 `bool`。

| 情况 | 返回 | 例子 |
| --- | --- | --- |
| 可能因外部条件失败，调用方**必须**处理 | `bool` + `RM_NODISCARD` | `xxx_init()`、`can_send()`、`robot_cmd_read()`（数据过期返回 false） |
| 纯计算，可能失败 | 结果通过输出参数返回，函数返回状态枚举（如 `AlgoStatus`） | `quat_ekf_update()`（发散） |
| 纯计算，不会失败 | 直接返回结果 | `angle_wrap_pi()`、`rpm_to_rad_s()` |
| 按接口约定不会失败 | `void`，并把前提写进 `@pre` | `motor_set_torque()`、`motor_group_send_all()` |

**不要**为了“看起来安全”给按约定不会失败的函数加上 `bool` 返回值。调用方会被迫写一堆永远不会走到的分支。

### 9.2 其他

- **必须**：模块函数的第一个参数是实例指针 `Xxx *self`；只读访问时用 `const Xxx *self`。
- **必须**：可调参数、协议常数用具名常量或配置项，不写魔法数字。显而易见的 `0`、`1`、数组下标**可以**直接写。
- **应该**：一个函数只做一件事；超过约 60 行时，考虑拆分。
- **应该**：参数超过 5 个时，改为传结构体。
- **应该**：检查失败时尽早返回，而不是层层嵌套 `if`。
- **必须**：不用函数指针表模拟多态，不用 `void *` 做通用接口。不同品牌、型号按 `type` 用 `switch` 分派，
  并且**品牌分支只出现在 `02_devices/motor/` 等设备目录内部**，`01_applic/` 不判断接的是 DJI 还是达妙。
  拿不准时，选新队员能直接读懂的写法。
- **必须**：硬件相关的初始化放在 `xxx_init()`（调度器启动前，配置外设）和 `xxx_start()`（调度器启动后，打开中断和 DMA）里；
  启动顺序只在 `01_applic/system/app_main.c` 的 `app_main()` 和 `startup_task()` 里写（《架构设计》运行时契约第 1 节）。

## 10. 宏与条件编译

- **应该**：能用 `static inline` 函数、`enum` 或 `const` 代替的，就不要写宏。
- 必须写宏时，**必须**给参数和整体都加括号；多条语句**必须**用 `do { … } while (0)` 包起来。
- **必须**：不写生成代码的宏（X-macro 等），也不用宏拼接函数名。
- **必须**：车和主控的差异放在 `01_applic/robot/robot_config.h` 和 `06_boards/` 里处理；`02_devices/` 和 `01_applic/` 的机构目录里不写 `#ifdef INFANTRY` 这类判断。
- **必须**：不用 `#if 0` 保留废弃代码，直接删除，需要时从 Git 历史里找回。

## 11. 中断与并发

- **必须**：中断处理函数里只做两件事：把数据放进环形缓冲区，或者通知任务。不调用控制逻辑，不调用话题函数，不打日志。
- **必须**：临界区里不延时、不调用任何阻塞函数，并且保持很短（拷贝一个快照的量级）。
- **必须**：任务里用 `rm_task_delay_until()` 或 `rm_task_delay()`，不用 `HAL_Delay()`。
- **必须**：每个话题实例只有一个发布者，在初始化时认领；`robot.c` 里在话题实例旁边注明发布者和读取者。
- **必须**：不能丢的信号（急停、遥控丢失、解锁）作为状态放在话题里，不作为事件放进事件队列。
- **必须**：只在中断里调用带 `FromISR` 后缀的 RTOS 接口，并且只在优先级数值不小于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的中断里调用。

## 12. 硬件访问

- **必须**：`HAL_` 函数、寄存器名、`stm32xxxx.h` 只出现在 `05_platform/<芯片>/` 和 `06_boards/` 中。
- **必须**：每个阻塞调用（SPI、I²C、Flash 等待）都有有限的超时。1 kHz 路径上的超时以毫秒计，不照抄 HAL 例程里的 `1000` 或 `HAL_MAX_DELAY`。
- **必须**：修改 CubeMX 配置并重新生成后，按 `06_boards/<板子>/REGEN_CHECKLIST.md` 逐条核对。

## 13. 错误处理

只有三种写法，没有第四种：

| 写法 | 用在 | 例子 |
| --- | --- | --- |
| `RM_ASSERT(cond)` | 编程错误：不该发生，一旦发生说明代码或配置写错了 | 初始化失败、话题被重复认领、在中断里调用话题函数 |
| `RM_CHECK(cond, ERR_XXX)` | 运行中可能发生、可以恢复的问题 | 外部数据非法（CRC、长度、NaN）、队列满、EKF 发散 |
| 返回 `bool` / 状态枚举 | 告诉调用方“没做成” | 见 9.1 |

- `RM_ASSERT` 在所有构建配置下**都会执行**括号里的表达式，只是失败后的处理不同。所以可以写 `RM_ASSERT(board_init())`。
- **必须**：会失败的初始化，失败时要有可见的出口：日志、指示灯、系统保持不可解锁三者至少有其一，关键设备三者都要有。**不允许**悄悄改用默认值或者忽略。
- **应该**：algorithm 层只返回状态，不打日志、不调用错误宏；由调用它的子系统记录错误并决定安全动作。

## 14. 安全相关代码

凡是涉及电机、安全门、看门狗、遥控丢失处理、执行器使能的代码，都属于安全相关代码。

- **必须**：不写“输出 0”，而是调用该机构规定的安全动作（零力矩、阻尼、失能、受控动作）。
- **必须**：电机指令只经过电机组的统一出口发送；全车停时出口把每个电机改写为它的 `stop_action`。机构停由子系统自己执行，出口不重复检查。
- **必须**：电机只在操作手解锁后请求使能；设备重新上线后**不**自动使能。
- **必须**：改动的提交说明或 PR 里附台架实测记录（测试条件、结果）。主机测试通过不等于上板安全。
- **应该**：至少两人审查。

## 15. 测试

- **必须**：`03_algorithm/` 里的算法、`02_devices/` 里的协议解析、状态机、安全门规则，都有主机单元测试。
- **应该**：每修复一个 bug，就加一个能复现它的测试。
- **应该**：断言检查**行为**（输出值、发出的帧），而不是检查“调用了几次”。
- **应该**：新增接口后，接上一个真实调用者，并确认它确实被链接进了固件（`tools/check_linked.py`）。

## 16. 文档

按“别人拿到这个模块，读头文件注释能否直接用对”来判断要不要单独写文档：

| 位置 | 要求 |
| --- | --- |
| `06_boards/<板子>/` | **必须**有 `README.md`（资源分配、接线）和 `REGEN_CHECKLIST.md` |
| `01_applic/robot/` | **必须**有 `README.md`：电机 ID 和接线、CAN 拓扑（哪两个节点开了终端电阻）、标定步骤 |
| `02_devices/` 下的设备驱动 | **应该**有 `README.md`：协议来源和版本、注意事项（如达妙设置零点前必须先失能） |
| `03_algorithm/`、`04_core/` 下的单个模块 | 头文件注释能说清楚用法的，**可以**不另写 README |

## 17. 第三方代码与许可证

- **必须**：不修改第三方代码目录；需要改变行为时，通过配置文件或钩子函数实现。
- **必须**：复制 MIT 等宽松许可证项目的代码时，保留原作者的版权声明，并在提交说明里写明来源。
- **必须**：**不复制 GPL 许可的代码**（例如 taproot），也不复制未声明许可证的代码，只借鉴思路。

## 18. 提交与审查

- **必须**：`CMakePresets.json` 里的**全部预设**都编译通过且 **0 警告**；代码已经用 `.clang-format` 格式化；主机测试通过。
- **必须**：提交说明的格式是 `类型: 做了什么`。类型有 `feat`、`fix`、`docs`、`build`、`test`、`refactor`、`chore`。
- **应该**：一次提交只做一件事。“搬代码”和“改行为”分成两次提交。

**代码审查清单：**

1. 接口的单位、坐标系、调用上下文写清楚了吗？
2. 新话题加进话题表了吗？
3. 新故障写清是全车停还是机构停、加进错误码表了吗？有没有和已有机制重复处理同一个故障？
4. control_task 的执行时间还在预算内吗？
5. 改了算法，有对应的测试吗？
6. 检查是不是只在边界做了一次，有没有层层重复（第 2 节）？
7. 安全相关的改动有台架记录吗（第 14 节）？
8. 特殊写法都有注释说明吗（6.1）？

## 19. 可选 C++ 模块

主语言是 C11（ADR 0012）。C++ 只在有明确收益时使用（个别复杂算法），并且：

- **必须**：对外只暴露 C 头文件（带 `extern "C"`），调用方看不出内部是 C++；
- **必须**：编译选项 `-fno-exceptions -fno-rtti -fno-threadsafe-statics`，不使用会抛异常的标准库接口；
- **必须**：不碰 RTOS 和 HAL；不定义带副作用的全局对象（全局构造函数的执行顺序不可控）。
