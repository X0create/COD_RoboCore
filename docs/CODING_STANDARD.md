# COD RoboCore 编码规范

本规范管的是仓库里手写的 C 代码：`05_platform/`、`04_core/`、`03_algorithm/`、`02_devices/`、`01_applic/`、`tests/`。下面三类不在管辖范围，也不要改：

- CubeMX 生成的代码。自己的代码只写在 `USER CODE BEGIN … END` 之间，区域里的代码同样按本规范写。
- 第三方代码：HAL、CMSIS、FreeRTOS、SEGGER RTT、Unity。需要改行为时用配置或钩子函数，别动源码。

规则的口气分三档：

| 用词 | 意思 |
| --- | --- |
| **必须** | 硬要求。违反了算缺陷，代码审查不通过。 |
| **应该** | 默认做法。没这么做，就在注释或提交说明里写清楚为什么。 |
| **可以** | 允许，自己判断。 |

每条规则背后基本都有一次讨论或一次踩坑，来龙去脉记在 `docs/ARCHITECTURE.md` 的 ADR 表里。第一次读可以先跳过，写到相关代码时再回头查。

## 1. 目标和取舍

### 1.1 想要什么样的代码

队里原有的《嵌入式代码规范》提了 8 条目标：简洁精炼、高效率、高复用可移植、高内聚低耦合、没有冗余、有规可循、特殊写法要说明、上手简单层级分明。本规范就是把这 8 条落成一条条具体规则，不再单列一章，边写边对照下面各节就行。

### 1.2 一处定义

这是"没有冗余"里最容易出事的一条，单独拎出来说：**同一个东西只有一个定义位置。**

- **一个参数，一个定义位置。** 同一个数（常数、换算系数、ID、总线号、阈值）只写一遍，别处引用它。注释里也不要再抄一遍具体数值——抄了迟早和代码对不上，写"见某文件"就行。各参数在哪，见 `01_applic/README.md` 的"参数在哪里"表。
- **一个状态，一个权威来源。** 一个状态只由一个对象持有、一个任务负责写；读的一方直接读它（或调它的读函数），不要另存一份副本再同步。比如全车模式只在 `safety_gate` 里，电池状态只在 indicator_task 里。
- **一项职责，一个负责模块。** 从初始化、启动到每个周期的处理都在同一个模块里，不拆到几个文件。比如状态灯和蜂鸣器只有 indicator_task 操作，CAN 接收和 bus-off 恢复都在 comm_rx_task。
- **同种工作不散乱。** 通用代码只写一份，放在 `01_applic/system/` 或对应机构目录下；`01_applic/config/` 只放"这台车跟别的不一样"的东西。

### 1.3 冲突时按什么顺序取舍

目标之间会打架：为了"高效率"省掉一次检查可能丢掉"正确"，为了"没有冗余"合并两段代码可能牺牲可读性。拿不准的时候按这个顺序：

**正确 > 可读与架构清晰 > 性能 > 额外的防御性检查**

- **正确**：功能符合需求，也符合接口约定。注意，**项目要求的安全机制属于"正确"，不属于"额外的防御性检查"，不能以性能或简洁为理由省略**——包括全车停（急停、遥控丢失）和它唯一的出口、机构停（本机构设备离线）、执行器安全动作、硬件看门狗、上电不自动使能。
- 但安全机制也不是越多越好：每个都要说得出防的是哪个具体故障；同一个故障已经有一处处理的，不加第二道；"以防万一"的检查、统计和报警不加。
- **可读与架构清晰**：新人顺着目录和注释能读懂，依赖方向符合分层规则。
- **性能**：满足实时预算就行，不为了几个时钟周期牺牲可读性；要优化先测量。
- **额外的防御性检查**：防"理论上可能、按接口约定不该发生"的情况，优先级最低，见第 2 节。

## 2. 检查只做一次：边界检查，内部按约定

输入在它进入系统的那道边界上检查一次，之后各层直接按接口约定用，不再重复检查。边界只有两类：

| 边界 | 检查什么 |
| --- | --- |
| 外部数据进入系统的地方：串口帧、CAN 帧、遥控、上位机、裁判系统、Flash 里的参数 | 帧长度、CRC、字段取值范围、NaN |
| 初始化和配置 | 配置能不能支撑（例如电机型号是否支持力矩指令）、资源冲不冲突（CAN ID、滤波器数量） |

边界之内：

- **必须**把前提条件写进接口注释的 `@pre`，由调用方负责满足。
- 不要在调用链的每一层重复检查同一个条件。比如电机型号支不支持力矩指令，在 `xxx_init()` 里查一次就够，运行时每个周期不再查。
- 不要在 1 kHz 的热路径上检查实例指针是否为 `NULL`：指针在初始化时就定了，写错的话上电测试就会暴露。
- `RM_ASSERT` 是用来抓**编程错误**的，放在初始化和公开接口入口合适，不要撒在热路径的每个函数里。

推荐写法：

```c
/* 在边界检查一次：设备层解析 CAN 帧时校验，上层直接使用 */
static void dji_motor_on_frame(DjiMotor *self, const CanFrame *frame)
{
    if (frame->len != 8)
    {
        self->bad_frame_count++;
        return;                     /* 帧不合法：丢弃，不喂狗 */
    }
    /* 解析、换算成 SI 单位、写入反馈快照 */
}
```

反例：

```c
/* 同一个条件层层重复：子系统、电机组、驱动各查一遍 */
void gimbal_step(Gimbal *self, ...)
{
    if (self == NULL || self->yaw_motor == NULL) { return; }
    if (!motor_supports_torque(self->yaw_motor)) { return; }   /* init 时已经查过 */
    ...
}
```

**安全机制不受"少检查"的影响。** 在线判断每个周期都要按时间戳算一遍；全车停的统一出口每个周期都要执行；遥控丢失、急停每个周期都要读。这些是项目要求的功能，不属于重复的防御性检查。

## 3. 文件与编码

- **必须**用 UTF-8（不带 BOM）、LF 换行、文件末尾留一个换行。`.gitattributes` 和 `.editorconfig` 已经在管这件事；从旧工程迁过来的 GBK 文件，先转码再提交。
- 头文件用 `#pragma once`，并且要能**单独编译**——自己 include 需要的全部头文件。
- 头文件加 `extern "C"` 保护，方便以后有 C++ 模块调用。
- **应该**一个模块对应一对 `xxx.c` / `xxx.h`，文件名就是模块名，全小写加下划线。
- 任务文件都放在 `01_applic/tasks/`。任务里只写"什么时候跑、按什么顺序调用谁"，具体计算放到 `modules/` 等文件里。
- 任务相关的命名统一以 `_task` 结尾：`detect_task.c`、入口函数 `detect_task_entry`、任务名 `"detect_task"`。反过来，不是任务的文件不要以 `_task` 结尾——`modules/ins/ins.c` 是算法，任务在 `tasks/ins_task.c`。
- **应该**按这个顺序 include，每组之间空一行：本模块自己的头文件 → C 标准库 → 本项目其他层 → 第三方库。
- 引用本项目其他层的头文件，**必须**从仓库根目录写起、带上层的编号，例如 `#include "05_platform/can/can.h"`、`#include "01_applic/modules/chassis/chassis.h"`；本模块自己的头文件和同目录头文件只写文件名，例如 `#include "chassis.h"`。
- 芯片厂商的头文件（CubeMX 生成的 `adc.h`、`spi.h`、`fdcan.h`，以及 HAL、CMSIS）**必须**用尖括号，例如 `#include <adc.h>`。原因：`05_platform/<外设>/` 里可能有本模块自己的同名接口头文件，用引号会先在当前目录找到它。
- **应该**在文件开头写 Doxygen 文件头：

```c
/**
 * @file    dji_motor.c
 * @brief   DJI 电机（M3508 / M2006 / GM6020）的协议解析与指令打包
 * @note    协议依据：《架构设计》附录 A.2
 */
```

## 4. 命名

标识符一律用英文，不用拼音，也不用拼音首字母。

- **类型**（结构体、枚举、typedef）用 `PascalCase`：`Motor`、`RobotCmd`、`StopAction`。
- **函数**用"模块_动作"，全小写加下划线，模块名就是文件名：`motor_set_torque()`、`dr16_read()`。
- **变量、结构体成员、参数**用 `snake_case`：`yaw_err_rad`、`feedback`。
- **宏和枚举常量**全大写，带模块前缀：`STOP_ACTION_DAMP`、`ERR_CAN_BUS_OFF`。
- **文件内的私有函数和变量**必须加 `static`，名字可以不带模块前缀，如 `static void parse_frame(...)`。
- **布尔变量和返回 bool 的查询函数**应该能读成一句话判断：`is_online`、`has_error`、`motor_is_enabled()`。

几点补充：

- `rm_` 前缀**只**留给会和 C 库或 FreeRTOS 重名的基础模块：`rm_time_*`、`rm_log_*`、`rm_task_*`、`rm_delay_*`、`rm_critical_*`（以及 `RM_` 开头的宏，如 `RM_ASSERT`、`RM_NODISCARD`）。其他模块不加前缀：`can_send()`、`watchdog_feed()`、`status_led_set()`。
- 同一个概念全仓库只用一个词。比如急停时电机的动作就叫 stop action：`StopAction`、`stop_action`、`motor_apply_stop_action()`；超时常量统一写成 `模块_TIMEOUT_MS`。
- 从旧工程迁过来的模块，第一版可以保留原函数名，第二步再改名（先搬代码、再改行为）。
- 缩写只用附录 A 里的，其他单词写全称。

### 4.1 单位后缀

物理量的单位靠名字表达，编译器不会替你检查，所以对跨模块边界的量要求最严，函数内部的临时量可以放宽：

- 公开接口——结构体成员、函数参数和返回值、共享数据的字段、`params.h` 里的常量——**必须**带单位后缀，或者在注释里写明单位。
- 模块内部的状态（`.c` 里的结构体成员、静态变量）**应该**带单位后缀。
- 函数里几行就用完、单位一眼能看出来的临时变量，可以不带。
- 无量纲的量（比例、计数、索引、布尔值）不需要后缀，比例建议写成 `_ratio`。

后缀的含义见《架构设计》的"单位后缀"表：`_rad`、`_rad_s`、`_m_s`、`_nm`、`_a`、`_v`、`_w`、`_ms`、`_us` 等。**对外接口一律用 SI 单位**；`_rpm`、`_deg`、`_raw` 只出现在设备层内部或配置输入里。

推荐写法：

```c
/* 公开字段带单位；函数内部短暂使用的临时量可以不带 */
typedef struct
{
    float yaw_target_rad;   /**< 目标航向，W 系，逆时针为正 */
    float yaw_ff_rad_s;     /**< 航向角速度前馈 */
} GimbalCmd;

static float wrap_error(float target_rad, float measure_rad)
{
    float err = target_rad - measure_rad;   /* 局部临时量，单位与参数相同 */
    return angle_wrap_pi(err);
}
```

反例：

```c
/* 公开字段没有单位，读者分不清是度还是弧度、是转子还是输出轴 */
typedef struct
{
    float yaw;
    float speed;
} GimbalCmd;
```

## 5. 格式

用仓库根目录的 `.clang-format` 统一格式化，提交前跑一次，**不要手动对齐去和它较劲**。

- 花括号用 Allman 风格，`{` 单独占一行。
- 缩进 4 个空格，每行不超过 100 列。
- `if` / `else` / `for` / `while` 的语句体必须加花括号，只有一行也加。
- 只有表格状的数据（寄存器表、参数表之类）可以用 `// clang-format off` / `// clang-format on` 保住手工排版，并且要写明原因（见 6.1）。

推荐：

```c
if (!is_online)
{
    return false;
}
```

反例：

```c
/* 没有花括号，后来的人想再加一行很容易写错 */
if (!is_online)
    return false;
```

## 6. 注释

注释用中文写，专业术语可以留英文，比如 CRC、DMA、Kp。

- 公开接口**必须**写 Doxygen 注释，写在头文件的声明处，`.c` 里的定义不再重复。按适用情况写全这几项：`@param` / `@return` 要写单位、坐标系、取值范围；`@pre` 写调用方必须满足的前提（见第 2 节）；`@note` 写调用上下文——能在任务里调，还是也能在中断里调。
- **应该**让注释解释**为什么**，而不是把代码复述一遍。硬件限制、数据手册勘误、看起来不对但实际是对的写法、被否决的方案，都值得写。
- `TODO` 和 `FIXME` **必须**带姓名和日期，例如 `/* TODO(xalve, 2026-09-25): ... */`。

```c
/**
 * @brief 设置电机输出轴力矩。
 * @param self       电机实例。
 * @param torque_nm  输出轴力矩，单位 N·m，正方向按 MotorConfig.direction 约定。
 * @pre   该电机在 motor_init() 时已确认支持力矩指令。
 * @note  只能在 control_task 中调用；本函数只写入电机组的槽位，不立即发送。
 */
void motor_set_torque(Motor *self, float torque_nm);
```

```c
/* 推荐：解释原因 */
/* 阻塞读取：17 字节约 18 µs，占 1 kHz 周期的 1.8%，改成 DMA 不值得（见 docs/budget.md） */

/* 反例：复述代码 */
/* 调用 spi_transfer 读取数据 */
```

### 6.1 这些写法必须说明

下面这些写法，读者一眼看不出用意，改错了往往还不报错。**必须**在旁边写注释说清楚"为什么非这样写不可"：

| 写法 | 例子 |
| --- | --- |
| 关闭自动格式化 | `// clang-format off` |
| 编译器属性、段放置、对齐 | `__attribute__((section(".dma_buf"), aligned(32)))`、`packed`、`weak` |
| `#pragma` | `#pragma GCC diagnostic ignored ...` |
| 内联汇编、内存屏障、Cache 操作 | `__DSB()`、`__ISB()`、`SCB_InvalidateDCache_by_Addr()` |
| 直接操作寄存器（只允许在 `05_platform/`、`06_boards/` 里） | `FDCAN1->TXBAR = ...` |
| 位运算技巧、定点换算、非常规的整数浮点转换 | `(x + 3) & ~3u`、协议里 12 位量的拼接 |
| 故意为之、看着像 bug 的写法 | 故意不加锁、故意丢弃返回值、`switch` 的贯穿（fall-through） |

推荐：

```c
/* H7 的 DMA1/DMA2 访问不到 DTCM，缓冲区必须放在 AXI SRAM；该段已由 MPU 设为不可缓存 */
RM_DMA_BUF static uint8_t dr16_rx_buf[2][18];
```

反例：

```c
/* 没有说明：以后有人"顺手"删掉这个宏，编译照样通过，运行时却什么都收不到 */
RM_DMA_BUF static uint8_t dr16_rx_buf[2][18];
```

## 7. 类型与数值

- **必须**用 `<stdint.h>` 的定宽整数类型表示协议字段和寄存器值（`uint8_t`、`int32_t` 等）；布尔值用 `<stdbool.h>` 的 `bool`。
- **必须**只用 `float`，不用 `double`：浮点常数带 `f` 后缀，数学函数用 `sinf`、`sqrtf`、`atan2f` 这类 `f` 版本，编译选项打开 `-Wdouble-promotion`。不带 `f` 的常数会把整个表达式拖成 double，在 F407 上是软件模拟运算，放在 1 kHz 控制环里代价很高。
- 在边界上把原始整数换算成 SI 浮点（第 2 节）；把浮点换算回协议整数时，**必须**先限幅再转换，不允许溢出回绕。
- 角度回绕**应该**统一用 `03_algorithm/` 里的函数，不要每处各写一遍 `while (x > PI)`。
- 判断"是否正常"的阈值**必须**与采样数量无关。比如判断静止要用**标准差**，不用峰峰值：峰峰值会随采样数增大，最后变成标定一直失败却没人发现——UniC 在陀螺零偏标定上真踩过这个坑。

推荐：

```c
const float gear_ratio = 3591.0f / 187.0f;
float out = sinf(angle_rad) * 0.5f;
```

反例：

```c
/* 3591.0 / 187 和 0.5 都是 double，sin() 也是 double 版本 */
float gear_ratio = 3591.0 / 187;
float out = sin(angle_rad) * 0.5;
```

## 8. 内存与存储期

- **必须**不调用 `malloc` / `free` / `calloc` / `realloc`。所有对象静态分配，或者由调用方提供存储。
- **必须**给全局变量加 `static`，其他文件通过函数访问；全局变量只写常量初值，和硬件相关的初始化放到显式的 `xxx_init()` 里。有一个例外：`01_applic/config/` 里的对象（设备、子系统、安全门）定义在 `objects.c`、声明在同目录的 `objects.h`，供 `01_applic/tasks/` 里的任务直接使用；其他层不得 include `objects.h`。
- **必须**不写递归，不用变长数组（VLA）；几百字节以上的缓冲区不要放栈上。
- DMA 缓冲区**必须**用 `RM_DMA_BUF` 声明，BDMA 缓冲区用 `RM_BDMA_BUF` 声明。
- `volatile` 只能用于硬件寄存器和中断里置位的简单标志，**不能**当任务之间的同步手段。跨任务共享的数据用 `watchdog_feed_data` / `watchdog_read_data` 或临界区。
- **应该**只在通信帧结构上用 `packed`，并且不要对 packed 结构体的成员取地址。
- **应该**把配置（`const XxxConfig`）和运行状态（`Xxx`）拆成两个结构体。

推荐：

```c
/* 调用方提供存储，初始化时关联配置 */
static const MotorConfig yaw_config = { .type = MOTOR_GM6020, .can_bus = CAN_BUS_1, .id = 1 };
static Motor yaw_motor;
```

反例：

```c
/* 运行时分配 */
Motor *yaw_motor = malloc(sizeof(Motor));
```

## 9. 函数与接口

### 9.1 返回值怎么定

按"失败会不会发生、调用方能不能处理"来选，不要求所有函数都返回 `bool`：

- 可能因外部条件失败、且调用方**必须**处理：返回 `bool` 加 `RM_NODISCARD`。例如 `xxx_init()`、`can_send()`、`robot_cmd_read()`（数据过期返回 false）。
- 纯计算、可能失败：结果从输出参数返回，函数返回状态枚举（如 `AlgoStatus`）。例如 `quat_ekf_update()` 发散。
- 纯计算、不会失败：直接返回结果。例如 `angle_wrap_pi()`、`rpm_to_rad_s()`。
- 按接口约定不会失败：返回 `void`，把前提写进 `@pre`。例如 `motor_set_torque()`、`motor_group_send_all()`。

不要为了"看起来安全"给按约定不会失败的函数加个 `bool`，那只会逼调用方写一堆永远走不到的分支。

### 9.2 其他

- **必须**让模块函数的第一个参数是实例指针 `Xxx *self`；只读访问用 `const Xxx *self`。
- **必须**把可调参数、协议常数写成具名常量或配置项，不写魔法数字。显而易见的 `0`、`1`、数组下标可以直接写。
- **应该**一个函数只做一件事；超过约 60 行就考虑拆。
- **应该**参数超过 5 个时改传结构体。
- **应该**检查失败尽早返回，不要层层嵌套 `if`。
- **必须**不用函数指针表模拟多态，不用 `void *` 做通用接口。不同品牌、型号按 `type` 用 `switch` 分派，而且**品牌分支只出现在 `02_devices/motor/` 这类设备目录内部**，`01_applic/` 不判断接的是 DJI 还是达妙。拿不准时，选新人能直接读懂的写法。
- **必须**把硬件相关的初始化分成两半：`xxx_init()` 在调度器启动前跑、配外设，`xxx_start()` 在调度器启动后跑、开中断和 DMA。启动顺序只在 `01_applic/system/app_main.c` 的 `app_main()` 和 `startup_task()` 里写（详见《架构设计》的运行时契约）。

## 10. 宏与条件编译

- **应该**能用 `static inline` 函数、`enum` 或 `const` 代替的，就不写宏。
- 非要写宏时，**必须**给参数和整体都加括号；多条语句**必须**用 `do { … } while (0)` 包起来。
- **必须**不写生成代码的宏（X-macro 等），也不用宏拼接函数名。
- **必须**把车和主控的差异放在 `01_applic/config/params.h` 和 `06_boards/` 里；`02_devices/` 和 `01_applic/` 的机构目录里不写 `#ifdef INFANTRY` 这类判断。
- **必须**不用 `#if 0` 保留废弃代码，直接删掉，需要时从 Git 历史里找。

## 11. 中断与并发

- **必须**让中断处理函数只做两件事：把数据放进环形缓冲区，或者通知任务。不调控制逻辑，不调 `watchdog_*` / `xxx_read()`，不打日志。
- **必须**保持临界区很短（拷贝一个快照的量级），里面不延时、不调用任何阻塞函数。
- **必须**在任务里用 `rm_task_delay_until()` 或 `rm_task_delay()`，不用 `HAL_Delay()`。
- **必须**让跨任务的数据由产生它的模块保存（模块对象里放数据 + watchdog，在线状态只看这一个），并且只有这个模块的 `.c` 写；别的模块只调它的 `xxx_read()`。
- **必须**把不能丢的信号（急停、遥控丢失、解锁）当状态保存，不要当事件塞进事件队列。
- **必须**只在中断里调用带 `FromISR` 后缀的 RTOS 接口，而且只在不低于 `configMAX_SYSCALL_INTERRUPT_PRIORITY`（优先级数值不小于它）的中断里调。

## 12. 硬件访问

- **必须**让 `HAL_` 函数、寄存器名、`stm32xxxx.h` 只出现在 `05_platform/<芯片>/` 和 `06_boards/` 里。
- **必须**给每个阻塞调用（SPI、I²C、Flash 等待）设有限的超时。1 kHz 路径上的超时以毫秒计，不要照抄 HAL 例程里的 `1000` 或 `HAL_MAX_DELAY`。
- **必须**在改过 CubeMX 配置并重新生成之后，按 `06_boards/<板子>/REGEN_CHECKLIST.md` 逐条核对。

## 13. 错误处理

只有三种写法，没有第四种：

- `RM_ASSERT(cond)`：抓编程错误——本不该发生，一旦发生说明代码或配置写错了。例如初始化失败、在中断里调 `watchdog_*`。
- `RM_CHECK(cond, ERR_XXX)`：处理运行中可能发生、可以恢复的问题。例如外部数据非法（CRC、长度、NaN）、队列满、EKF 发散。
- 返回 `bool` 或状态枚举：告诉调用方"没做成"，见 9.1。

另外几件事：

- `RM_ASSERT` 在所有构建配置下都会执行括号里的表达式，只是失败后的处理不同，所以可以写 `RM_ASSERT(board_init())`。
- **必须**给会失败的初始化留一个看得见的出口：日志、指示灯、系统保持不可解锁，三者至少占一个；关键设备三个都要有。**不允许**悄悄改用默认值或者直接忽略。
- **应该**让 algorithm 层只返回状态，不打日志、不调用错误宏；由调用它的子系统记录错误并决定安全动作。

## 14. 安全相关代码

凡是碰电机、安全门、看门狗、遥控丢失处理、执行器使能的代码，都算安全相关代码。

- **必须**不写"输出 0"，而是调用该机构规定的安全动作（零力矩、阻尼、失能、受控动作）。
- **必须**让电机指令只通过电机组的统一出口发送；全车停时由出口把每个电机改写成它自己的 `stop_action`。机构停由子系统自己执行，出口不重复判断。
- **必须**让电机只在操作手解锁后请求使能；设备重新上线后**不**自动使能。
- **必须**在提交说明或 PR 里附上台架实测记录（测试条件、结果）。主机测试通过不等于上板安全。
- **应该**至少两人审查。

## 15. 测试

- **必须**给 `03_algorithm/` 里的算法、`02_devices/` 里的协议解析、状态机、安全门规则写主机单元测试。
- **应该**每修一个 bug，就补一个能复现它的测试。
- **应该**断言检查**行为**（输出值、发出的帧），而不是检查"调用了几次"。
- **应该**新增接口后接一个真实调用者，并确认它确实被链接进固件（`tools/check_linked.py`）。

## 16. 文档

判断标准很简单：别人拿到这个模块，只读头文件注释能不能用对。用不到单独文档的就不写。

- `06_boards/<板子>/` **必须**有 `README.md`（资源分配、接线）和 `REGEN_CHECKLIST.md`。
- `01_applic/config/` **必须**有 `README.md`：电机 ID 和接线、CAN 拓扑（哪两个节点开了终端电阻）、标定步骤。
- `02_devices/` 下的设备驱动**应该**有 `README.md`：协议来源和版本、注意事项（比如达妙设置零点前必须先失能）。
- `03_algorithm/`、`04_core/` 下的单个模块，头文件注释能说清楚用法的，可以不另写 README。

## 17. 第三方代码与许可证

- **必须**不修改第三方代码目录；要改行为就用配置文件或钩子函数。
- 复制 MIT 这类宽松许可证项目的代码时，**必须**保留原作者的版权声明，并在提交说明里写明来源。
- **必须**不复制 GPL 许可的代码（例如 taproot），也不复制没声明许可证的代码——只借鉴思路。

## 18. 提交与审查

- 提交前**必须**：`CMakePresets.json` 里的全部预设都编译通过且 0 警告，代码已经用 `.clang-format` 格式化，主机测试通过。
- 提交说明的格式是 `类型: 做了什么`，类型取 `feat`、`fix`、`docs`、`build`、`test`、`refactor`、`chore` 之一。
- **应该**一次提交只做一件事。"搬代码"和"改行为"分成两次提交，审查的人才看得清。

审查时逐条过这份清单：

1. 接口的单位、坐标系、调用上下文写清楚了吗？
2. 新的共享数据有 `xxx_read()`、写明超时了吗？
3. 新故障写清是全车停还是机构停、加进错误码表了吗？有没有和已有机制重复处理同一个故障？
4. control_task 的执行时间还在预算内吗？
5. 改了算法，有对应的测试吗？
6. 检查是不是只在边界做了一次，有没有层层重复（第 2 节）？
7. 安全相关的改动有台架记录吗（第 14 节）？
8. 特殊写法都有注释说明吗（6.1）？

## 19. 可选 C++ 模块

主语言是 C11。C++ 只在有明确收益时用（个别复杂算法），并且：

- **必须**对外只暴露 C 头文件（带 `extern "C"`），让调用方看不出内部是 C++；
- **必须**开 `-fno-exceptions -fno-rtti -fno-threadsafe-statics`，不用会抛异常的标准库接口；
- **必须**不碰 RTOS 和 HAL，不定义带副作用的全局对象（全局构造函数的执行顺序不可控）。
