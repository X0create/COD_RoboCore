# supercap/：设备：超级电容

**状态：主控侧驱动已完成（编译 + 电脑单元测试通过），协议是草案（版本 1），电容板固件还没实现，没有上板。**

- `supercap.c/.h`：电容控制板（cap-pcmc，STM32G474）的 CAN 通信：主控发指令（允许输出、功率上限、缓冲能量），
  电容板回反馈（错误、是否在输出、电容电压、底盘功率、剩余能量）。
- 用法和电机相同：`robot_init()` 里 `supercap_init()`；comm_rx_task 收帧交给 `supercap_receive()`；
  使用方 `supercap_read()`；control_task 每周期 `supercap_send()`（内部限频，10 ms 一帧）。
- 电容板是经典 CAN（1 Mbit/s），**只能接经典 CAN 总线**（MC02 上是 FDCAN1 或 FDCAN2，和电机共用）；
  FDCAN3 是 CAN FD，接上去会把整条总线搞乱，`supercap_init()` 会拒绝。
- 功率上限目前用 `robot.h` 里的固定值；裁判系统解析做好之后，改成裁判系统 0x0201 给的底盘功率上限和 0x0202 的缓冲能量。

## 通信协议（草案，版本 1）

两个 ID 都在 `robot.h` 的 `supercap_config` 里配置，默认指令 `0x061`、反馈 `0x062`，不能和同一路总线上的电机重复。
全部是 8 字节经典帧（标准 ID、数据帧），多字节数据**小端**（低字节在前）。

### 主控 → 电容：指令帧（默认 ID 0x061，每 10 ms 一帧）

| 字节 | 内容 | 类型 | 分辨率 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 标志位 | uint8 | | 第 0 位 = 1：允许电容板向底盘输出；其余位保留为 0 |
| 1–2 | 底盘功率上限 | uint16 | 0.1 W | 如 600 = 60.0 W；电容板按它控制从电池取的功率 |
| 3–4 | 裁判系统缓冲能量 | uint16 | 0.1 J | 不知道时为 0 |
| 5 | 协议版本 | uint8 | | 当前为 1 |
| 6–7 | 保留 | | | 为 0 |

**电容板必须做到：** 超过 100 ms 收不到指令帧（主控死机、线断了）就停止输出、只让电池直接供电。
这是电容板这边唯一的通信失效保护，主控不会再替它判断。

### 电容 → 主控：反馈帧（默认 ID 0x062，每 1 ms 一帧）

| 字节 | 内容 | 类型 | 分辨率 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 错误标志 | uint8 | | 0 = 正常；各位含义由电容组定，定了写进这里 |
| 1 | 状态标志 | uint8 | | 第 0 位 = 1：正在向底盘输出；其余位保留为 0 |
| 2–3 | 电容组电压 | uint16 | 0.01 V | 如 2350 = 23.50 V |
| 4–5 | 底盘功率 | int16 | 0.1 W | 电容板测到的底盘用电功率；电机回馈充电时为负 |
| 6 | 剩余能量 | uint8 | | 0–255 对应 0–100% 可用能量 |
| 7 | 协议版本 | uint8 | | 当前为 1；主控收到版本不对的帧直接丢弃 |

主控超过 50 ms 收不到合法反馈就判电容离线（detect_task 的日志里会打印 `supercap offline`）。

### 改协议的规矩

两边任何一处字段改了，就把两边的协议版本号同时加 1，并更新这张表。版本不一致时主控丢弃反馈帧，
日志里电容一直离线，不会把错位的数据当成真的用。
